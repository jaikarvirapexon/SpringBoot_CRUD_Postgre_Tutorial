### F-001 — Dependency vulnerability scan did not complete within review budget

- Source: deps-scan/dependency-check-maven
- Severity: Low
- Detail: Per the Maven stack's audit-tool mapping, `mvn org.owasp:dependency-check-maven:check -DfailBuildOnCVSS=7` was invoked against `pom.xml` (no manifest change in this diff — this is the mandatory baseline check per Step 3, not diff-specific). The plugin blocked on `Existing update in progress; waiting for update to complete` against the local NVD data-cache lock (`~/.m2/repository/.../dependency-check-data/11.0/odc.update.lock`) and had not produced a report after ~55 seconds of active waiting; the process was terminated to keep the review within budget rather than let it run unattended for the NVD feed's typical multi-minute-to-hour first-sync window.
- Manual baseline note (informational only, not a scored finding — not tool-confirmed): `pom.xml` pins `spring-boot-starter-parent` 3.0.6 (EOL branch) with `postgresql` resolved transitively via the Spring Boot 3.0.6 BOM. Advisory `CVE-2024-1597` (pgjdbc SQL injection when `preferQueryMode=SIMPLE`) affects pgjdbc versions bundled by several Spring Boot 3.0.x BOM releases prior to 42.7.2/42.5.5/42.4.4/42.3.9. This project does not set `preferQueryMode`, so the default (`EXTENDED`) is not exploitable via this vector, and `pom.xml` is unchanged by this diff regardless. Flagging for the fix-loop/CI to confirm with an actual completed `dependency-check` (or `mvn versions:display-dependency-updates`) run rather than asserting it here without tool evidence.
- Fix: Re-run `mvn org.owasp:dependency-check-maven:check` in CI where the NVD cache is pre-warmed/persistent across runs (per `spring-boot-patterns` — no CI workflow exists yet in this repo despite `CLAUDE.md` declaring `ci: github-actions`); do not gate this story's merge on it since `pom.xml` is untouched by the diff.
- Not a blocker (tool-incomplete maps to `tool_missing` treatment per `security-assessment` skill).
